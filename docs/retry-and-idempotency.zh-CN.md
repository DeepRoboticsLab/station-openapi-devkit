# 重试与结果确认

**语言：** [English](retry-and-idempotency.md) | 简体中文

SDK 只对连接失败或超时的查询自动重试。下载、写入和控制均不自动重试。

## 1. 默认尝试次数

下表次数包含第一次调用：

| 调用类型                 | 默认最多尝试 | 说明                                       |
|--------------------------|-------------:|--------------------------------------------|
| 查询、列表、分页、状态   |            2 | 仅连接失败或超时时再次尝试                 |
| 文件下载                 |            1 | 数据直接写入调用方，失败时可能留下部分输出 |
| 任务下发、控制和取消     |            1 | 可能已经被平台接收                         |
| 任务模板创建、启停和删除 |            1 | 可能已经修改平台数据                       |
| 设备、充电和摄像机控制   |            1 | 重复命令可能影响现场设备                   |

HTTP 错误、平台明确返回的业务失败、参数错误和响应解析错误不会自动重试。

`RequestOptions.RetryPolicy.NEVER` 可以关闭查询的默认重试；任何请求级选项都不能开启下载、写入和控制的重试。

## 2. resultUnknown

写入或控制调用发生连接中断、读取超时等情况时，请求可能已经到达平台，但调用方没有收到最终响应。此时 SDK 异常会返回：

```text
resultUnknown=true
```

它不表示成功或失败，而是表示当前结果尚未确认。处理顺序是：

1. 不要立即重复调用；
2. 保存异常中的 `requestId`、`operation`、`code` 和发生时间；
3. 通过查询 API、RocketMQ 消息或现场状态确认原操作是否生效；
4. 只有确认原操作没有生效，并且业务允许时，才重新执行。

常见确认方式：

| 原操作                   | 建议确认方式                       |
|--------------------------|------------------------------------|
| 任务下发、控制、取消     | 查询任务执行记录或等待任务状态消息 |
| 任务模板创建、启停、删除 | 查询模板详情或模板分页             |
| 四足狗控制               | 查询设备状态和实时坐标             |
| 摄像机或云台控制         | 结合设备状态或现场确认             |

批量取消按列表顺序处理，首个失败即停止；已取消任务不回滚。即使收到明确业务失败，也应逐项查询状态后再处理剩余任务。

模板停用会清除未执行任务；启用不自动下发。启停结果未知时，检查模板详情的 `isEnable` 和关联执行记录。

下载的连接、超时或输出失败也会标记 `resultUnknown=true`
。重新下载前须丢弃不完整输出，详见[文件下载](file-download-guide.zh-CN.md)。

## 3. requestId

SDK 将 `requestId` 放入 `X-Request-Id` 和调用异常中。未设置时自动生成，查询重试沿用同一个值。

它不是业务幂等键，不能依靠重复使用相同 `requestId` 阻止重复操作。客户应用需要根据自己的业务标识判断任务、结果或消息是否已经处理。

MQ 去重和结果合并见[RocketMQ 消息接入](mq-events-guide.zh-CN.md)。
